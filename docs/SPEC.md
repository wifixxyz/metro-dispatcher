# Метро · Диспетчер — спецификация

Браузерная игра «Метро · Диспетчер»: реалистичный симулятор поездного диспетчера.
Первая линия — Некрасовская (15) Московского метро. Ответы и документация — по-русски.
Работаем итерациями (см. [ROADMAP.md](ROADMAP.md)); каждая итерация заканчивается
рабочей задеплоенной версией.

## 1. Процесс

- GitHub-репозиторий: wifixxyz/metro-dispatcher. Работа ведётся с актуальным main.
- В начале каждого чата читать README.md, docs/ROADMAP.md, CHANGELOG.md;
  docs/SPEC.md — только нужные разделы.
- Каждое изменение — отдельная ветка и PR с описанием; версия по semver (с 0.1.0),
  запись в CHANGELOG.md.
- CI (GitHub Actions): typecheck, lint, Vitest, сценарные прогоны, сборка;
  деплой на GitHub Pages после мержа в main.
- После каждой итерации отдать: ссылку на PR, ссылку на задеплоенную игру,
  краткий список изменений и отчёт о проверках с цифрами. Писать только о том,
  что реально запускалось.
- Если требование неоднозначно или физически неправдоподобно — спросить до кода.
- Не добавлять функций сверх текущей итерации без согласования.

## 2. Стек (решено)

- TypeScript (strict) + Vite.
- PixiJS v8 (WebGL) для карты; pixi-viewport для пана и зума (жесты + кнопки).
- UI-панели — чистый TS + CSS, без фреймворка.
- PWA: vite-plugin-pwa (манифест, иконки, офлайн, полноэкранный режим).
- Сохранения — IndexedDB (idb-keyval). Конфиги валидируются через zod.
- Звук — Web Audio API, звуки синтезируются в коде, без чужих сэмплов.
- Вибрация — navigator.vibrate (с проверкой поддержки).
- Тесты — Vitest (ядро и сценарии) + Playwright (смоук-тест на мобильном вьюпорте).
- Целевая платформа — Android-телефоны, в т.ч. Яндекс Браузер; ПК тоже должен работать.

## 3. Архитектура

```
src/core/      — чистая логика, БЕЗ DOM и Pixi (запускается в Node):
  graph.ts        — путевой граф: узлы, рельсовые участки с длиной, стрелки
  interlocking.ts — блок-участки, светофоры, маршруты: замыкание маршрута,
                    замыкание приближения, защита флангов, постепенное размыкание
  physics.ts      — поезд: масса, разгон, служебное и экстренное торможение,
                    ограничения скорости (стрелки, кривые, оборот), длина состава
  alsars.ts       — коды АЛС-АРС по свободности участков впереди
  dispatcher.ts   — автодиспетчер: интервал, расчёт парка, выпуск/возврат в депо,
                    выбор оборотного пути, регулировка нагона/отставания
  sim.ts          — фиксированный шаг (напр. 50 мс), ускорение = больше шагов за кадр,
                    seeded RNG, журнал событий
src/lines/     — конфиги линий (JSON + zod-схема); nekrasovskaya.json — первая
src/render/    — PixiJS: слои путей, сигналов, поездов, подписей, LOD при зуме
src/ui/        — панели, выбор режима, карточка поезда, ручное управление
src/audio/, src/haptics/, src/storage/
src/editor/    — редактор линий
tests/         — unit-тесты ядра, сценарные прогоны, Playwright
```

Главный принцип: всё, что относится к конкретной линии (станции, пути, стрелки,
светофоры, тупики, депо, режимы), живёт в конфиге. В коде ядра нет названий станций.

## 4. Конфиг линии (nekrasovskaya.json)

Станции по порядку: Некрасовка, Лухмановская, Улица Дмитриевского, Косино,
Юго-Восточная, Окская, Стахановская, Нижегородская.

- Пути I и II. Первые четыре станции — островные платформы, остальные — береговые.
- Длины перегонов и ограничения скорости — по открытым источникам; если точных
  данных нет, ставить правдоподобное значение с пометкой `"approx": true` и
  перечислять такие места в отчёте.
- Обороты:
  - Некрасовка: два оборотных пути за станцией, последовательный проход горловины,
    возврат на I путь.
  - Лухмановская: два оборотных пути у депо «Руднево», независимая занятость,
    общая горловина под защитой.
  - Косино: оборот через съезд I↔II, без остановки на стрелке.
  - Окская: оборот через один съезд, отдельные маршрутные светофоры.
  - Нижегородская: три тупика; боковые короткие и не используются, средний — рабочий.
- Депо «Руднево» у Лухмановской: два деповских пути, выпуск только на I путь
  в сторону конечной.
- Режимы: Некрасовка или Лухмановская — до Нижегородской / Окской / Косино
  (6 вариантов). Неиспользуемый участок затемнён.

## 5. Геймплей

- Автодиспетчер: игрок задаёт интервал; диспетчер считает парк (оборотное время /
  интервал), запрашивает составы из депо в безопасные окна, возвращает лишние,
  восстанавливает график.
- Ручное управление поверх автомата (переключатель авто/ручной для всей линии
  и для отдельного узла):
  - задать маршрут: тап по начальному светофору, затем по конечному;
  - отменить маршрут (с выдержкой времени, если маршрут замкнут приближением);
  - перевести стрелку (только если участок свободен и не замкнут);
  - задержать или отправить поезд со станции, отправить состав в депо.
- Интерлокинг не даёт открыть конфликтующие маршруты ни автомату, ни игроку.
  Отказ объясняется коротким сообщением.
- Ускорение 1×–8×, шаг 1×, пауза.

## 6. Внешний вид — «пульт диспетчера»

- Тёмный фон, схема в стиле табло ДЦХ: свободные пути — приглушённые,
  замкнутый маршрут — белый/жёлтый, занятый участок — красная подсветка,
  розовый цвет линии 15 как акцент.
- Сигналы с лёгким свечением; крупные поезда-маркеры с номером и стрелкой
  направления; хвост поезда показывает его длину.
- Интервальные часы на станциях, отклонение от графика цветом.
- Нижняя панель: интервал, в работе / расчётно / не хватает, статус автомата,
  скорость времени. Диагностика и журнал событий — в выдвижной шторке.
- Тапы — минимум 44 px, без случайных срабатываний при пане. Плавные 60 fps
  на среднем Android.

## 7. Звук и вибрация

Щелчок стрелки, сигнал при занятии маршрута, тревога при экстренном торможении
или застревании, тихий фон зала. Короткая вибрация на действия, длинная на тревоги.
Всё отключается в настройках.

## 8. Сохранения и статистика

Автосохранение смены в IndexedDB, продолжение после перезапуска. Статистика:
график фактических интервалов по станциям, выполнение парка, число задержек
и ручных вмешательств, журнал сбоев.

## 9. Редактор линий

Сначала импорт и экспорт JSON с валидацией и понятными ошибками, плюс
предпросмотр на карте. Потом визуальное редактирование: станции, участки,
стрелки, светофоры. Любая валидная линия должна запускаться ядром без правок кода.

## 10. Обязательные проверки (в CI)

- Unit: интерлокинг (конфликтующие маршруты, защита флангов, размыкание),
  физика (тормозной путь, соблюдение ограничений), АЛС-АРС.
- Сценарии: каждый из 6 режимов × интервалы 2 / 3 / 5 мин × ускорение 8×,
  ≥2 ч модельного времени, фиксированный seed. Инварианты:
  - никогда два поезда в одном блок-участке или на одной стрелке;
  - нет поездов, стоящих дольше порога (deadlock);
  - нет одновременно открытых конфликтующих маршрутов;
  - поезд не превышает разрешённую скорость;
  - фактический интервал в пределах ±15% от заданного после выхода на режим;
  - смена интервала на ходу (2 → 5 → 2) отрабатывает.

  Результаты — таблицей в отчёте.
- Playwright: игра загружается на вьюпорте 390×844, карта рисуется,
  кнопки работают, PWA-манифест валиден.
